You don't need an account or an API key. Each request costs half a cent or a cent in USDC, paid from your own wallet with [x402](/developers/pay-per-request), and an x402 client library makes the payment for you.

You can check the connection first. The [status endpoint](/api-reference/general/get-api-status) is free and returns the latest indexed slot and data freshness.

```bash
curl --fail "https://api.fabriq.trade/v1/status"
```

<Steps>
  <Step title="Fund a wallet with USDC">
    Use a Solana or Base wallet that holds a little USDC: $1 pays for 100 to 200 requests. You don't need SOL or ETH for fees. On Solana the facilitator pays the network fee, and on Base the payment is a gasless authorization.

    Put the wallet's private key in an environment variable:

    ```bash
    # Solana: the base58 secret key, as Phantom and Solflare export it
    export SOLANA_PRIVATE_KEY="<your base58 secret key>"
    # Base: the 0x-prefixed hex private key
    export EVM_PRIVATE_KEY="0x<your private key>"
    ```

    <Warning>
      Anyone with this key can spend the wallet's funds. Use a dedicated wallet that holds only what you plan to spend on API requests, and keep the key out of source control.
    </Warning>
  </Step>
  <Step title="Install a client and fetch the top trending pools">
    Pick your language, then the file for your wallet's network. Each example pays $0.005 for `GET /trending/pools?limit=5`.

    <X402Examples />
  </Step>
  <Step title="Read the output">
    The program prints the top five pools, then the receipt of the payment:

    ```text
    1 SOL/USDC 18.42
    2 JUP/SOL 12.07
    3 ...
    Paid on solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp, transaction <transaction signature>
    ```

    Every API response has the same shape: the result in `data`, and freshness and paging details in `meta`. Pools are shown as **base** and **quote** tokens.

    ```json
    {
      "data": [
        {
          "rank": 1,
          "address": "5rCf1DM8LjKTw4YqhnoLcngyZYeNnQqztScTogYHAS6",
          "dex": "meteora_dlmm",
          "base": { "mint": "So11111111111111111111111111111111111111112", "symbol": "SOL", "side": "x" },
          "quote": { "mint": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v", "symbol": "USDC", "side": "y" },
          "liquidity_usd": 1338416.3,
          "fab_score": 18.42,
          "stats": { "h1": { "volume_usd": 2841120.5, "lp_fees_usd": 1136.45, "apr_pct": 0.17 } }
        }
      ],
      "meta": { "as_of": "2026-11-08T14:02:11Z", "indexed_slot": 478213990 }
    }
    ```

    The receipt comes from the `PAYMENT-RESPONSE` header: base64 JSON with the settlement `transaction` and its `network`. You're only charged when a request succeeds.
  </Step>
</Steps>

<Tip>
  If the program prints `402` with `Payment rejected: insufficient_funds` on Base, or `Payment rejected: invalid_exact_svm_payload_transaction_simulation_failed` on Solana, the wallet most likely doesn't hold enough USDC on that network. See [Errors](/developers/pay-per-request#errors) for the other cases.
</Tip>

Have an API key? Skip the wallet and send the key in the `X-API-Key` header instead. See [API keys](/developers/authentication).
