title: API keys

---

You don't need a key to use the API: [pay per request with x402](/developers/pay-per-request) from any Solana or Base wallet. An API key is the alternative when you want an invoice instead of paying per request, or when your client can't sign x402 payments, such as the MCP connectors in Claude, ChatGPT, Cursor and VS Code.

| | Pay per request (x402) | API key |
| --- | --- | --- |
| How | x402 payment in the `PAYMENT-SIGNATURE` header | `X-API-Key` header |
| Account | None: pay from any Solana or Base wallet | Issued by the Fabriq team |
| Cost | $0.005 or $0.01 per request, in USDC | Per plan |
| Limits | Per paying wallet ([Rate limits](/developers/rate-limits)) | Per key ([Rate limits](/developers/rate-limits)) |
| See | [Pay per request (x402)](/developers/pay-per-request) | Below |

`GET /status` and `GET /dexes` are free and need neither.

## Send your key

Send your key in the `X-API-Key` header:

```bash
curl "https://api.fabriq.trade/v1/tokens/JUPyiwrYJFskUPiHa7hkeR8VUtAeFoSYbKedZNsDvCN" \
  -H "X-API-Key: $FABRIQ_API_KEY"
```

- An invalid key gets `401 unauthorized`.
- A request with no key and no payment gets `402 payment_required`, with the x402 challenge that says how to pay for it.
- When a request carries both a key and a payment, the key is used and the payment is ignored.

The [MCP server](/developers/mcp) also accepts `Authorization: Bearer <key>`, or the key in the path at `https://api.fabriq.trade/mcp/k/<key>` for clients that only accept a server URL.

## Keep your key secret

- Call the API from your server, not from a browser or mobile app, where anyone can read the key.
- Store the key in an environment variable or a secret manager, not in source control.
- If you put a key in an MCP URL, treat the URL as the secret, and use a separate key for it.
- If a key leaks, ask the Fabriq team to revoke it and issue a new one.

## Getting a key

Contact the Fabriq team to request an API key.
