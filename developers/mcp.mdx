title: MCP server

Fabriq runs an [MCP](https://modelcontextprotocol.io) server, so assistants and agents such as Claude Code, Cursor and VS Code can look up tokens, pools, LP opportunities and wallets on their own. It serves the same data as the REST API, as twelve read-only tools designed around the questions agents ask.

```text
https://api.fabriq.trade/mcp
```

The server uses the Streamable HTTP transport, stateless: each call is a plain request and response.

## Connect

Agents built on an x402-aware MCP client need no key: they [pay for each tool call with x402](#pay-per-call-with-x402), from their own wallet.

The apps below connect with an [API key](/developers/authentication). Send it as `Authorization: Bearer <key>` or `X-API-Key: <key>` to `/mcp`. For clients that only accept a URL, use `https://api.fabriq.trade/mcp/k/<key>`. Fabriq validates the key in the URL before connecting. If you also supply a header key, that key takes precedence for tool calls.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http fabriq https://api.fabriq.trade/mcp \
      --header "Authorization: Bearer $FABRIQ_API_KEY"
    ```
  </Tab>
  <Tab title="Cursor">
    In `~/.cursor/mcp.json`, or `.cursor/mcp.json` in a project:

    ```json
    {
      "mcpServers": {
        "fabriq": {
          "url": "https://api.fabriq.trade/mcp",
          "headers": { "Authorization": "Bearer YOUR_FABRIQ_API_KEY" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="VS Code">
    In `.vscode/mcp.json`. VS Code asks for the key once and stores it securely:

    ```json
    {
      "inputs": [
        { "type": "promptString", "id": "fabriq-key", "description": "Fabriq API key", "password": true }
      ],
      "servers": {
        "fabriq": {
          "type": "http",
          "url": "https://api.fabriq.trade/mcp",
          "headers": { "Authorization": "Bearer ${input:fabriq-key}" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Claude app">
    In Claude, open **Customize → Connectors** and add a custom web connector named Fabriq. If your connector form offers **Request headers**, enter `https://api.fabriq.trade/mcp`, select **No sign in**, and add `X-API-Key` with your key. If your form only accepts a URL, use the following URL with your key and select **No sign in**.

    ```text
    https://api.fabriq.trade/mcp/k/YOUR_FABRIQ_API_KEY
    ```

    Connector availability depends on your plan and workspace settings. [Claude connector setup](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)
  </Tab>
  <Tab title="ChatGPT">
    If prompted, enable **Developer mode** under **Settings → Security and login**. Open [ChatGPT Plugins](https://chatgpt.com/plugins), select the plus button, and choose **Add custom MCP server**. Enter Fabriq as the name and the following URL as the connection. Choose **No authentication** in ChatGPT because Fabriq checks the key in the URL.

    ```text
    https://api.fabriq.trade/mcp/k/YOUR_FABRIQ_API_KEY
    ```

    Create the plugin and check that ChatGPT discovers the Fabriq tools. Custom MCP access depends on your account and workspace settings. [OpenAI setup guide](https://developers.openai.com/plugins/deploy/connect-chatgpt#add-the-mcp-server)
  </Tab>
  <Tab title="Other clients">
    Any MCP client that supports Streamable HTTP works. Point it at `https://api.fabriq.trade/mcp` with an `Authorization: Bearer <key>` header or, if it can't send headers, at `https://api.fabriq.trade/mcp/k/<key>`.
  </Tab>
</Tabs>

<Warning>
  A URL with your key in it works like a password: anyone who has it can spend your key's limits. Use a separate key for each app you connect, keep the URL out of screenshots and shared chats, and ask the Fabriq team to revoke the key if the URL leaks. A URL with an unknown key fails to connect.
</Warning>

## Tools

Every tool is read-only. Lists default to 10 results and page with `cursor`, using `next_cursor` from the previous answer.

| Tool | Use it for | x402 price |
| --- | --- | --- |
| `find_token` | A token's mint from its symbol or name, best match first | $0.005 |
| `get_token` | Price, FDV, supply, holders, liquidity, links and audit flags | $0.005 |
| `get_token_price_history` | USD candles, 1 minute to 1 week (at most 200) | $0.005 |
| `find_pools` | Pools for a token or pair, by DEX and liquidity | $0.005 |
| `get_pool` | A pool's liquidity, fees, volume, APR, score and quality verdict | $0.005 |
| `get_pool_activity` | A pool's recent swaps or liquidity events | $0.005 |
| `get_trending_pools` | Fabriq's ranking of LP opportunities, with category and other filters | $0.005 |
| `get_wallet_overview` | Net worth, balances, open and closed LP totals | $0.01 |
| `get_wallet_positions` | Open positions (valued on chain) or closed ones | $0.01 open, $0.005 closed |
| `get_wallet_pnl` | Realized PnL for a period: total, by day or by pool | $0.005 |
| `get_wallet_lp_score` | The 30-day LP score and rank | $0.01 |
| `get_wallet_activity` | Recent opens, deposits, withdrawals, claims and closes | $0.005 |

Pool tools return a summary by default: the fields that matter for choosing a pool, with 1-hour and 24-hour stats. Pass `detail: "full"` for the complete [Pool](/api-reference/introduction#pools) object. Other tools return what the matching REST endpoint returns, without image URLs.

Agents usually know a symbol, not a mint, so start from `find_token`. Many tokens copy famous symbols: the tool lists Jupiter-verified tokens first and returns `is_verified` and liquidity for each candidate.

## Resources and prompts

The MCP server publishes these resources.

| Resource URI | Contents |
| --- | --- |
| `fabriq://docs/data-coverage` | Data sources, freshness, and history |
| `fabriq://docs/supported-dexes` | Guide to supported programs |
| `fabriq://docs/pnl-and-lp-score` | Position lifecycles, PnL, and LP score |
| `fabriq://dexes` | Supported programs as JSON |

The available prompts are `analyze_wallet` for reviewing wallet performance and `find_lp_opportunities` for comparing pools. The standard `/mcp` endpoint lists tools, resources, and prompts without a key or payment.

## Limits

Each tool call counts as one request against the paying wallet's or the API key's [rate limits](/developers/rate-limits). Listing and reading resources don't count.

## Pay per call with x402

Each tool call can be paid in USDC on Solana or Base with [x402](/developers/pay-per-request), following the x402 MCP transport, at the price in the [tools table](#tools). An x402-aware MCP client handles this for you, the same way an x402 HTTP client does for the REST API.

<Steps>
  <Step title="Call a tool">
    Without a key or payment, the result is an error whose `structuredContent` is the x402 `PaymentRequired` object, also written as JSON text in `content`. Its `resource.url` is `mcp://tool/<name>` and `accepts` lists the ways to pay, at the tool's price.
  </Step>
  <Step title="Pay and call again">
    The client signs a payment for one offer and repeats the call with the payment in `params._meta["x402/payment"]`.
  </Step>
  <Step title="Get the result and the receipt">
    Fabriq verifies the payment, runs the tool, then settles. The result carries the settlement in `_meta["x402/payment-response"]`.
  </Step>
</Steps>

```json Paid call
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "find_token",
    "arguments": { "query": "jup" },
    "_meta": {
      "x402/payment": {
        "x402Version": 2,
        "accepted": { "scheme": "exact", "network": "eip155:8453", "amount": "5000", "...": "..." },
        "payload": { "...": "..." }
      }
    }
  }
}
```

As with REST, only successful calls are charged: a call that fails (an invalid argument, an unknown pool) is not settled, and the same payment can be sent again. A settled payment can't be reused. Paying wallets are limited to 300 calls a minute.
