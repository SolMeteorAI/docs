---
title: Rate limits
description: How many requests your key can make, and what to do when you hit the limit.
---

Limits apply per API key, or per paying wallet for [pay-per-request](/developers/pay-per-request) callers.

| Access | Requests per minute | Requests per day |
| --- | --- | --- |
| API key (beta) | 60 | 50,000 |
| x402, per paying wallet | 300 | 100,000 |

Requests without a key or a valid payment are also limited per IP address.

Batch endpoints count as one request: `GET /tokens?mints=...` with 100 mints costs the same as one token. On the [MCP server](/developers/mcp), each tool call counts as one request.

<Note>
  Plans and limits for general availability are not final. Contact the Fabriq team if you need more during the beta.
</Note>

## Headers

Every response carries your current budget:

| Header | Meaning |
| --- | --- |
| `X-RateLimit-Limit` | Requests allowed in the current window. |
| `X-RateLimit-Remaining` | Requests left in the current window. |
| `X-RateLimit-Reset` | Seconds until the window resets. |

## When you hit the limit

The API answers `429 rate_limited` with a `Retry-After` header in seconds. Wait that long before retrying.

```javascript
async function fabriq(path) {
  for (let attempt = 0; attempt < 5; attempt++) {
    const response = await fetch(`https://public-api.fabriq.trade/v1${path}`, {
      headers: { "X-API-Key": process.env.FABRIQ_API_KEY },
    });
    if (response.status !== 429) {
      return response.json();
    }
    const wait = Number(response.headers.get("Retry-After") ?? 1);
    await new Promise((resolve) => setTimeout(resolve, wait * 1000));
  }
  throw new Error("Rate limited");
}
```

## Using fewer requests

- Batch token lookups with `GET /tokens?mints=...` (up to 100 mints).
- Don't poll faster than the data changes. Trending scores move every second, 24-hour stats every 10 seconds, LP score ranks every hour. See [Data coverage](/developers/concepts/data-coverage#freshness).
- Use `GET /portfolio/{wallet}` for a wallet's summary (net worth, top balances, open positions, PnL) instead of combining several calls.
